# DeskMate デモシナリオ設計書

版: 2.0（Raspberry Pi 内完結・3 状態構成）/ 最終更新: 2026-07-27

実カメラなしで DeskMate の全機能を確認・実演するための、
ダミー入力シナリオ、デモ時系列、実演台本、確認チェックリストを定義する。

数値の根拠と閾値は [status-definition.md](status-definition.md)、
実装インターフェースは [architecture.md](architecture.md) §17 を参照。

> **版 1.0 からの変更**: 8 シナリオ → 5 シナリオ。7 状態 → 3 状態。
> 共有画面のデモを削除し、休憩促しのデモを追加。

---

## 1. ダミーシナリオ 5 種

`src/deskmate/input/scenarios.py` の `SCENARIOS`。
`ScenarioSpec` の各フィールドは [architecture.md](architecture.md) §17 を参照。
座標は正規化（0.0–1.0）で書き、`RegionMap` の既定矩形と対応させる。

### S1 `keyboard_focus` — キーボード付近で一定した細かな動き → **集中**

| 項目 | 値 |
|------|-----|
| `label` | キーボード付近で一定した動き |
| `base_rate_eps` | 1400.0 |
| `rate_jitter` | 0.15 |
| `burst_period_s` | None（連続） |
| `burst_duty` | 1.0 |
| `centers` | `((0.50, 0.82),)` |
| `sigma_px` | 22.0 |
| `drift_px_per_s` | 1.0 |
| `uniform_noise_ratio` | 0.03 |
| `dropout` | False |

**期待**: 開始 5 秒後から `focused`（集中）。キャラクターが `running.gif`。
根拠: `rate_short ≈ 1400 >= focus_min_eps(400)`、keyboard 領域の `share ≈ 0.96 >= 0.60`、
`area_short ≈ 0.06 <= 0.20`、`rate_cv_10s ≈ 0.07 <= 0.60`。

**このシナリオは休憩促しのデモにも使う**（集中が続くため）。

### S2 `mouse_intermittent` — マウス付近で断続的な動き → **非集中**

| 項目 | 値 |
|------|-----|
| `label` | マウス付近で断続的な動き |
| `base_rate_eps` | 2000.0 |
| `rate_jitter` | 0.25 |
| `burst_period_s` | 1.0 |
| `burst_duty` | 0.60 |
| `centers` | `((0.86, 0.80),)` |
| `sigma_px` | 17.0 |
| `drift_px_per_s` | 3.0 |
| `uniform_noise_ratio` | 0.03 |
| `dropout` | False |

**期待**: `idle`（非集中）。キャラクターが `sitting.gif`。
断続的なので `rate_cv_10s ≈ 0.75 > 0.60` となり集中の条件を満たさない。

**制約**: `burst_period_s` は `features.ema_short_seconds`（1.0 秒）より短くすること。
長くすると休止中に `rate_short` が落ちて誤って `away` に向かう。

### S3 `desk_wide` — 机上の広い範囲で活発な動き → **非集中**

| 項目 | 値 |
|------|-----|
| `label` | 机上の広い範囲で活発な動き |
| `base_rate_eps` | 4000.0 |
| `rate_jitter` | 0.30 |
| `centers` | `((0.20, 0.35), (0.50, 0.45), (0.80, 0.30), (0.45, 0.75))` |
| `center_switch_s` | 1.2 |
| `sigma_px` | 60.0 |
| `drift_px_per_s` | 22.0 |
| `uniform_noise_ratio` | 0.06 |
| `dropout` | False |

**期待**: `idle`（非集中）。`area_short ≈ 0.36 > 0.20` かつ `focus_share` が低いので
集中の条件を満たさない。版 1.0 の `organizing` はこのシナリオに相当したが、
3 状態化により `idle` に統合された。

**デモでの説明**: 「動きが大きくても、キーボード周りに集中していなければ『非集中』です」。

### S4 `quiet` — ほぼ無活動 → **離席中**

| 項目 | 値 |
|------|-----|
| `label` | 動きがほとんどない |
| `base_rate_eps` | 20.0（微小なセンサノイズのみ） |
| `rate_jitter` | 0.50 |
| `centers` | `((0.50, 0.50),)` |
| `sigma_px` | 110.0 |
| `uniform_noise_ratio` | 1.00（全面ノイズ） |
| `dropout` | False |

**期待**: `away_seconds`（30 秒）後に `away`（離席中）。キャラクターが `sleeping.gif`。
それまでは `idle`。

**重要**: このシナリオは「席を外した」場合と「着席して静止している」場合の
両方を表す。DeskMate はこれを区別できない（[status-definition.md](status-definition.md) §10）。
**デモではこの限界に触れてよいが、UI には注記を出さない。**

### S5 `dropout` — 入力が途切れる

| 項目 | 値 |
|------|-----|
| `label` | 入力が途切れる |
| `dropout` | True（`read()` が `None` を返し続ける） |

**期待される挙動**:

| 経過 | 内部 | 表示 |
|------|------|------|
| 0–1.5 秒 | `STREAMING` のまま | 直前の状態 |
| 1.5 秒〜 | `STALLED`。空窓を刻み `idle_seconds` が伸びる | 直前の状態（やがて `away` へ向かう） |
| 5.0 秒〜 | `SystemStatus.NO_SIGNAL`。空窓生成を停止 | 「入力が途切れています」 |
| 復帰後 | `STARTING` から再ウォームアップ | 「起動中です」→ 通常表示 |

## 2. 詳細画面で見せる推定過程

右クリックメニューから開く。

| # | 見せるもの | パネル |
|---|-----------|-------|
| 1 | イベントカメラが取得した点群 | `EventScatterPanel`（間引き最大 5,000 点。正極性=暖色、負極性=寒色、領域矩形を重ねる） |
| 2 | 時間窓の情報 | ヘッダ（窓番号 / 200 ms / イベント数） |
| 3 | 動きの範囲 | `MotionPanel`（bbox 矩形 + 幅・高さ・面積比） |
| 4 | 動きの中心位置 | `MotionPanel`（重心マーカー + 直近 20 窓の軌跡） |
| 5 | 動きの速度 | `MotionPanel`（`centroid_speed` / `event_rate_delta`） |
| 6 | 領域ごとの活動量 | `RegionPanel`（6 領域の横棒 + 16×16 グリッドのヒートマップ） |
| 7 | 抽出した特徴量 | `FeatureTablePanel` |
| 8 | 推定した状態 | `StatusHeader`（状態名・信頼度・適用ルール ID・候補状態・得票数） |
| 9 | キャラクター | `CharacterView` |
| 10 | 継続時間と連続集中 | `StatusHeader` + `HistoryPanel`（直近 5 分の帯グラフ） |

画面上部の固定表示: `PRIVACY_NOTICE_JA` / 入力ソース名 / `SourceStatus` / `PipelineStats`。

**入力ソース名は必ず表示する。** Pi 上で意図せずダミーになっていないかを判別するため。
例: `metavision(live)` / `dummy(demo) — metavision_core が見つかりません`。

## 3. デモモードの時系列 `DEMO_SEQUENCE`

`input/scenarios.py` に定義する。合計 **210 秒（3 分 30 秒）** で 1 周する。

各ステップは最小状態継続時間（3 秒）の 5 倍以上を確保している。

| # | シナリオ | 長さ | 期待される状態 | キャラクター | 見どころ |
|:-:|---------|:----:|--------------|------------|---------|
| 1 | `keyboard_focus` | 50 s | `idle` →(約 8 s) `focused` | 座る → 走る | 集中の確定。**休憩促しもここで出す**（§3.1） |
| 2 | `mouse_intermittent` | 35 s | `idle` | 座る | 動きはあるが断続的なので非集中 |
| 3 | `desk_wide` | 30 s | `idle` | 座る | 動きが大きくても集中ではない |
| 4 | `quiet` | 55 s | `idle` →(30 s) `away` | 座る → 寝る | 離席中の判定。30 秒の猶予 |
| 5 | `keyboard_focus` | 25 s | `away` → `idle` → `focused` | 寝る → 座る → 走る | 復帰の様子 |
| 6 | `dropout` | 15 s | `no_signal` | 座る | 入力途絶時の挙動 |

```python
DEMO_SEQUENCE = (
    DemoStep("keyboard_focus",     50.0),
    DemoStep("mouse_intermittent", 35.0),
    DemoStep("desk_wide",          30.0),
    DemoStep("quiet",              55.0),
    DemoStep("keyboard_focus",     25.0),
    DemoStep("dropout",            15.0),
)
```

### 3.1 休憩促しをデモで出す

本来 25 分かかるので、デモでは短縮する。

```yaml
break:
  demo_scale: 0.02      # 25分 -> 30秒、リセット3分 -> 3.6秒
```

または起動時に `--break-demo` を付けると `demo_scale = 0.02` になる。

ステップ 1（`keyboard_focus`、50 秒）で `focused` が約 42 秒続くため、
**30 秒地点で休憩促しが出る**。キャラクターが `break.gif` に切り替わり、
「そろそろ休憩しませんか」バナーが表示される。

ステップ 2 以降は `idle` なので、3.6 秒後に連続集中がリセットされ、バナーが消える。

## 6. デバッグモード

`debug.enabled: true`（または `--debug`）のとき、詳細画面に表示する。

| 操作 | 動作 |
|------|------|
| シナリオ選択 | 5 シナリオを手動で選択 |
| 状態固定ボタン（3 状態 + 解除） | 推定を無視して状態を固定。キャラクターの見え方を即座に確認できる |
| 休憩促しを今すぐ出す | `break_due` を強制的に立てる |
| ウォームアップスキップ | `warmup_seconds` を 0 にする |

状態固定中は詳細画面とウィジェットに「デバッグ: 状態固定中」を表示する。
**デモ本番では `debug.enabled: false` にすること。**

## 7. トラブル時の代替デモ

| 症状 | 代替手段 |
|------|---------|
| 実機のカメラが認識されない | `--source dummy` に切り替えてデモを続行する。台本はそのまま使える |
| 状態が期待どおり遷移しない | デバッグモードで状態を手動固定し、キャラクターの見え方だけを見せる |
| 詳細画面が重い（Pi） | `ui.detail.refresh_hz` を 5、`max_preview_points` を 2000 に下げる |
| 時間が足りない | ステップ 1（集中 + 休憩促し）→ ステップ 4（離席中）だけを見せる |
