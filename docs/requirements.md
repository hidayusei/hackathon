# DeskMate 要件定義書

版: 2.0（Raspberry Pi 内完結・3 状態構成）/ 最終更新: 2026-07-27

本書は DeskMate の「何を作るか」を定義する。
「どう作るか」は [architecture.md](architecture.md)、状態の定義値は [status-definition.md](status-definition.md)、
プライバシー要件は [privacy-design.md](privacy-design.md) を参照する。

> **版 1.0 からの変更**: Raspberry Pi 内で完結する構成に変更。状態を 7 種から 3 種へ削減。
> 共有画面を廃止（将来の展望として保留）。キャラクターをドット絵 GIF に変更。休憩促しを追加。

---

## 1. プロジェクトの目的

モニタ上部に設置したイベントカメラで机上の動きを取得し、ユーザの状態を 3 種類に推定して、
**Raspberry Pi の画面上で動くドット絵のキャラクター**として表現する。

目的は次の 3 点である。

1. **作業状態を可愛く可視化する。** 集中していれば恐竜が走り、手が止まれば座り、
   動きが無くなれば寝る。数値やグラフではなく、ひと目で伝わるキャラクターの動作で示す。
2. **働きすぎを止める。** 集中が 25 分続いたらキャラクターが休憩を促す。
3. **プライバシーを保って状態を取る。** 机上には書類・スマートフォン・PC 画面・私物が並ぶ。
   RGB 画像を一切使わず、輝度変化のみを取得するイベントカメラを用いる。
   既定では Raspberry Pi 内で完結する。利用者が明示的に有効化した場合に限り、
   同一 LAN 内の指定 PC へ生イベントを UDP で送信できる。

## 2. 解決する課題

| # | 課題 | DeskMate での解決 |
|---|------|------------------|
| C1 | 集中しすぎて休憩を取り忘れる | 連続集中 25 分でキャラクターが休憩を促す |
| C2 | 自分がどれだけ集中していたか分からない | 状態と継続時間を常駐ウィジェットに表示する |
| C3 | 作業状況の可視化に Web カメラを使うと机上が写り込む | イベントカメラのみを使い、RGB 画像を取得しない |
| C4 | PC に常駐ソフトを入れたくない / PC の負荷を上げたくない | 処理を Raspberry Pi 側へ完全にオフロードする。PC には何も入れない |
| C5 | 状態表示が頻繁に切り替わると信用されない | 平滑化（多数決・最小継続時間）を必須要件とする |
| C6 | 真面目な計測ツールは続かない | キャラクターの動作で表現し、見ていて楽しいものにする |

### 明示的な非目標

- 個人の識別。誰が机の前にいるかは判定しない。
- 作業内容の推定。アプリ名・書類の内容・入力文字列は扱わない。
- 生産性のスコアリング。DeskMate は評価指標を出さない。
- 高精度な行動認識。MVP はルールベースであり、推定は「傾向」に留まる。
- インターネットや外部サービスへの共有。UDP は同一 LAN の指定 PC への生イベント転送に限る。

## 3. 想定ユーザ

### U1: 本人（プライマリ）

- 大学の研究室・オフィスで 1 日数時間デスクワークをする人。
- 机の上に Raspberry Pi 5 + 小型ディスプレイ + GenX320 を置ける。
- 自分の作業リズムを把握したい / 集中しすぎて休憩を忘れがち。
- 技術的知識は不要。起動したら放っておくだけ。

### U2: 開発者 / デモ実施者（MVP 期間中の主要ユーザ）

- ハッカソンで実演する実装者。
- **Windows で開発し、Raspberry Pi で動かす。** 両方で同じコードが動く必要がある。
- 実カメラなしでも全機能を確認できる必要がある（ダミー入力）。
- 推定の過程を説明できる必要がある（詳細画面）。

## 4. ユースケース

### UC-1: Pi の画面で状態を眺める（U1）

1. Raspberry Pi でカメラの準備を済ませ、DeskMate を起動する。
2. 常駐ウィジェットが画面隅に最前面で表示される。
3. キャラクター・状態名（日本語）・継続時間が表示される。
4. 作業を始めると恐竜が走り出す。手を止めると座る。席を立つと寝る。

### UC-2: 休憩を促される（U1）

1. 集中状態が連続 25 分続く。
2. キャラクターが `break` アニメーション（跳ねて手を振る）に切り替わる。
3. ウィジェット内に「そろそろ休憩しませんか」バナーが出る。
4. 「あとで」を押すと 5 分後に再提示。「休憩する」を押すと連続集中がリセットされる。
5. 実際に手が止まって 3 分経つと、自動的にリセットされる。

**音は鳴らさない。ポップアップウィンドウも出さない。** 作業の邪魔をしないこと。

### UC-3: 推定過程を確認する（U1 / U2）

1. ウィジェットを**右クリック**してメニューから「詳細」を選ぶ。
2. 詳細画面が開き、点群 → 時間窓 → 動きの範囲 → 重心 → 領域別活動量 → 特徴量 → 状態
   が並んで表示される。
3. 閉じると点群の配信は停止する（詳細画面が開いている間だけ配信される）。

### UC-4: 推定を止める（U1）

1. ウィジェットの停止ボタン、または右クリックメニューから「停止」を選ぶ。
2. 入力の取り込みと推定が停止し、表示が「推定を停止しています」に変わる。
3. 再開すると起動時と同じくウォームアップからやり直す。

### UC-5: Windows で UI を開発する（U2）

1. Windows で `python -m deskmate --demo` を実行する。
2. `input.source: auto` が Metavision の不在を検出し、自動的にダミー入力になる。
3. **設定ファイルを書き換えずに** 3 状態とキャラクター 4 種を確認できる。

### UC-6: デモを行う（U2）

1. デモモードで起動する。
2. ダミー入力がシナリオを自動で切り替え、3 状態が順に遷移する。
3. `break.demo_scale` を下げておくと、休憩促しも短時間で実演できる。

## 5. 機能要件

### 入力（FR-IN）

| ID | 要件 | 優先度 |
|----|------|--------|
| FR-IN-1 | イベント入力は `EventSource` インターフェースで抽象化し、推定処理と UI が入力方式に依存しないこと | 必須 |
| FR-IN-2 | **Raspberry Pi 上で Metavision SDK からライブ受信できること**（`MetavisionEventSource`） | 必須 |
| FR-IN-3 | ダミーデータ生成ソースを提供すること | 必須 |
| FR-IN-4 | ファイル（JSONL / NPZ）読み込みソースを提供すること | 必須 |
| FR-IN-5 | **`source: auto` により、同じ設定ファイルで Pi と Windows の両方が起動できること** | 必須 |
| FR-IN-6 | Windows で `metavision_core` を import せずに起動できること（遅延 import） | 必須 |
| FR-IN-7 | 1 イベントは `x` / `y` / `t`(µs) / `p`(0/1) を持つこと | 必須 |
| FR-IN-8 | 入力が途切れた場合に、停止せず `no_signal` 状態へ遷移すること | 必須 |
| FR-IN-9 | HDF5 録画データ読み込み（ECF コーデックの制約あり。[architecture.md](architecture.md) §7.3） | 任意 |
| FR-IN-10 | PC が同一 LAN 上の Pi から UDP 生イベントを `EventSource` として受信できること | 必須 |
| FR-IN-11 | UDP の欠損・重複・順序逆転で終了せず、不完全バッチを破棄すること | 必須 |

### UDP 転送（FR-NET）

| ID | 要件 | 優先度 |
|----|------|--------|
| FR-NET-1 | Pi は生イベントを同一 LAN の単一ユニキャスト IPv4 宛先へ複製送信できること | 必須 |
| FR-NET-2 | `udp.output.enabled` と `privacy.allow_external_send` が共に true の場合だけ送信すること | 必須 |
| FR-NET-3 | 送信は既定無効で、broadcast・multicast・公開 IP を拒否すること | 必須 |
| FR-NET-4 | datagram 上限を守り、連番と fragment 番号で再構成できること | 必須 |
| FR-NET-5 | 生イベントを送受信側のいずれでも保存しないこと | 必須 |

### 処理（FR-PR）

| ID | 要件 | 優先度 |
|----|------|--------|
| FR-PR-1 | イベント列を 100〜1000 ms の時間窓に分割すること（既定 200 ms） | 必須 |
| FR-PR-2 | [status-definition.md](status-definition.md) §5 の特徴量を各窓で算出すること | 必須 |
| FR-PR-3 | 机上を領域に分割し、領域ごとの活動量を算出すること | 必須 |
| FR-PR-4 | 領域定義を設定ファイルから変更できること | 必須 |
| FR-PR-5 | **状態を離席中 / 集中 / 非集中の 3 種に推定すること** | 必須 |
| FR-PR-6 | 推定はルールベースで行い、後から学習モデルへ差し替えられること | 必須 |
| FR-PR-7 | 推定は単一窓ではなく過去数秒〜数十秒の履歴を用いること | 必須 |
| FR-PR-8 | 平滑化により状態が 3 秒未満で切り替わらないこと | 必須 |
| FR-PR-9 | 各状態の継続時間を秒単位で管理すること | 必須 |
| FR-PR-10 | **連続集中時間を計測し、25 分で休憩促しフラグを立てること** | 必須 |
| FR-PR-11 | 休憩促しは「あとで」でスヌーズでき、非集中が 3 分続くとリセットされること | 必須 |
| FR-PR-12 | 1 窓（200 ms）の処理を 30 ms 以内に完了すること | 必須 |

### 出力・UI（FR-UI）

| ID | 要件 | 優先度 |
|----|------|--------|
| FR-UI-1 | **常駐ウィジェットと詳細画面の 2 画面**を提供すること | 必須 |
| FR-UI-2 | 常駐ウィジェットは最前面表示・移動・最小化ができること | 必須 |
| FR-UI-3 | **現在の状態を日本語で表示すること** | 必須 |
| FR-UI-4 | 継続時間を表示すること | 必須 |
| FR-UI-5 | **キャラクターを 30×30 のドット絵 GIF で表示すること** | 必須 |
| FR-UI-6 | GIF は最近傍補間で整数倍拡大すること（ドット絵を崩さない） | 必須 |
| FR-UI-7 | 状態に応じてアニメーションが切り替わること（走る / 座る / 寝る / 休憩促し） | 必須 |
| FR-UI-8 | **右クリックメニューから詳細画面を開けること** | 必須 |
| FR-UI-9 | 詳細画面に推定過程を表示すること | 必須 |
| FR-UI-10 | 休憩促し時にバナーと「あとで」「休憩する」ボタンを表示すること | 必須 |
| FR-UI-11 | **画面に注意書き・免責・内部指標を常時表示しないこと**（[status-definition.md](status-definition.md) §1-6） | 必須 |
| FR-UI-12 | Pi の画面いっぱいに表示するフルスクリーンモードを持つこと | 任意 |

### プライバシー（FR-PV）

[privacy-design.md](privacy-design.md) に PV-1〜PV-11 として定義する。

### 動作確認（FR-TE）

| ID | 要件 | 優先度 |
|----|------|--------|
| FR-TE-1 | **Windows で実カメラなしに全画面・全状態を確認できること** | 必須 |
| FR-TE-2 | ダミー入力で 3 状態と入力途絶を再現できること | 必須 |
| FR-TE-3 | シナリオが時間経過で自動遷移するデモモードを提供すること | 必須 |
| FR-TE-4 | `break.demo_scale` で休憩促しを短時間で実演できること | 必須 |
| FR-TE-5 | 特徴量計算・状態推定・平滑化・休憩促しに単体テストがあること | 必須 |

## 6. 非機能要件

| ID | 分類 | 要件 |
|----|------|------|
| NFR-1 | 性能 | 1 窓（200 ms）あたりの特徴量抽出＋推定を 30 ms 以内に完了する |
| NFR-2 | 性能 | **Raspberry Pi 5 上で常駐時の CPU 使用率が 1 コア換算 25% 未満** |
| NFR-3 | 性能 | 詳細画面の点群描画は最大 5,000 点。Pi では更新頻度を下げられること |
| NFR-4 | 応答性 | UI スレッドをブロックしない。推定処理はワーカースレッドで実行する |
| NFR-5 | 堅牢性 | 入力ソースの例外でアプリが終了しない。再接続を試みる |
| NFR-6 | 移植性 | **Raspberry Pi OS（aarch64）と Windows 11 の両方で起動できる** |
| NFR-7 | 移植性 | 同一のコード・同一の設定ファイルで両環境が動くこと |
| NFR-8 | 保守性 | 入力・特徴量・推定・UI が疎結合であり、それぞれ単体でテストできること |
| NFR-9 | 国際化 | 表示文字列は日本語を既定とし、定義を 1 箇所に集約すること |

## 7. 対象範囲

### 対象

1. Raspberry Pi 上での Metavision ライブ入力
2. 時間窓分割・特徴量抽出（全体 + 領域別）
3. 3 状態のルールベース推定と平滑化
4. 継続時間の管理と休憩促し
5. ドット絵 GIF キャラクターの表示
6. 常駐ウィジェット・詳細画面
7. ダミー入力による Windows 上での動作確認
8. 同一 LAN 内の Pi から PC への任意の UDP 生イベント転送

### 対象外

- Raspberry Pi のドライバ導入・カメラ初期化（`dtoverlay` / `rp5_setup_v4l.sh`）。
  DeskMate 起動前に済ませておく前提とする（[architecture.md](architecture.md) §26.1）
- インターネット、クラウド、第三者サービスへの共有
- Discord / Slack 等の外部サービス連携、クラウド保存
- 深層学習モデルの開発
- 実カメラでの閾値キャリブレーション（手順のみ定義。[architecture.md](architecture.md) §24.3）

## 8. 前提と制約

| # | 前提 / 制約 |
|---|------------|
| A1 | 使用機材は **Raspberry Pi 5 + Prophesee GenX320（320×320）** |
| A2 | Prophesee 公式イメージでドライバと OpenEB が導入済み。`metavision_viewer` でライブ映像が出ることを確認済み |
| A3 | `metavision_core` は **Linux 専用**。Windows では利用できない |
| A4 | イベント座標系はセンサ座標（左上原点）。既定 320×320 |
| A5 | イベント時刻 `t` はセンサ基準の単調増加マイクロ秒 |
| A6 | カメラはモニタ上部から机上を俯瞰する固定設置。設置後に動かさない |
| A7 | 領域（キーボード付近など）は設定ファイルで矩形指定する。自動キャリブレーションは行わない |
| A8 | 想定ユーザは 1 名。複数人の机は対象外 |
| A9 | **イベントカメラは「離席」と「着席して静止」を区別できない。**「離席中」は推定である（[status-definition.md](status-definition.md) §10） |
| A10 | 照明変化・モニタのちらつき・人の通過はノイズとして混入しうる。安全側の `idle` に落ちる設計とする |

## 11. 用語

| 用語 | 定義 |
|------|------|
| イベント | 画素の輝度変化 1 件。`(x, y, t, p)` |
| 極性 (p) | 輝度増加=1、輝度減少=0 |
| バッチ (EventBatch) | 入力ソースが一度に返すイベント列 |
| 時間窓 (Window) | 特徴量算出の単位。既定 200 ms |
| 領域 (Region) | 机上を分割した矩形 |
| 抽象状態 (DeskStatus) | 離席中 / 集中 / 非集中 の 3 種 |
| 連続集中 (focus streak) | `focused` が途切れずに続いた秒数。休憩促しの根拠 |
| 休憩促し (break prompt) | 連続集中が閾値を超えたときの表示。状態ではなくフラグ |
| 活動量 (eps) | 1 秒あたりのイベント数 |
