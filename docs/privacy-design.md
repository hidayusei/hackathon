# DeskMate プライバシー設計書

版: 2.0（Raspberry Pi 内完結・3 状態構成）/ 最終更新: 2026-07-27

机の上には、書類・スマートフォン・PC 画面・私物といった個人情報が並ぶ。
DeskMate はそれらを「見ない」ことを前提に設計する。

> **版 2.0 で最大の変化**: システムが **Raspberry Pi 内で完結**するようになった。
> PC への送信が無くなり、ネットワークを一切使わない。共有画面も廃止したため、
> **データが端末の外に出る経路が設計上ひとつも存在しない**。

**重要な前提**: イベントカメラを使っているから安全、とは言わない（§5）。
本書は「リスクをゼロにする」文書ではなく、「何を取得せず、何を外に出さないか」を明示する文書である。

## 1. プライバシー要件一覧

| ID | 要件 | 実装上の担保 | 検証 |
|----|------|------------|------|
| PV-1 | RGB 画像を使用しない | 依存に撮像系ライブラリを入れない。入力は `EventBatch`（x, y, t, p）のみを受け取る型で固定する | `requirements.txt` レビュー、`EventSource` の型 |
| PV-2 | PC 画面や書類の内容を取得しない | 画面キャプチャ API・ファイル走査・アクティブウィンドウ取得を実装しない | `mss` / `pyautogui` / `win32gui` を import しない |
| PV-3 | 生のイベントデータを原則保存しない | `privacy.save_raw_events` の既定 `false`。保存は `PrivacyGuard` を通らないと実行できない | `tests/test_privacy_guard.py` |
| PV-4 | **ネットワーク送信を一切行わない** | 送信系ライブラリを依存に含めない。`SourceKind` から `websocket` / `tcp` / `udp` / `http` を削除済み | 依存レビュー、`SourceKind` の定義 |
| PV-5 | 状態推定は端末内で完結する | 全処理が `src/deskmate/pipeline/` 内。クラウド API を使わない | 依存レビュー |
| PV-6 | 詳細画面を閉じている間、点群を生成しない | `DetailFrame` は `set_detail_subscription(True)` の間だけ生成する | `tests/test_runner.py` |
| PV-7 | ユーザが推定処理を停止できる | ウィジェットの停止ボタン / 右クリックメニュー。停止中は入力の読み取り自体を止める | `tests/test_runner_control.py` |
| PV-8 | 状態履歴の保存期間を設定できる | `privacy.history_retention_minutes`（既定 60）。`DurationTracker` が期限切れを破棄 | `tests/test_duration.py` |
| PV-9 | デバッグ用保存機能は初期状態で無効 | `privacy.save_raw_events` / `save_features` / `logging.log_features` / `debug.enabled` すべて既定 `false` | `tests/test_config.py` |
| PV-10 | イベントデータからも形状や動きが推測されうることを明記 | **README と本書に記載する。UI には常時表示しない**（§3.3） | ドキュメントレビュー |
| PV-11 | 「イベントカメラだから完全に匿名・安全」と表現しない | 全ドキュメント・全 UI 文言のレビュー項目 | §5 の禁止表現リスト |

版 1.0 の PV-6（外部共有は抽象状態のみ）と PV-8（共有停止）は、
**共有機能そのものを廃止したため不要になった。**

## 2. データの分類と扱い

| レベル | 名称 | 具体例 | プロセス内 | 画面表示 | 保存 | 端末外へ |
|:-----:|------|--------|:---------:|:--------:|:----:|:--------:|
| L0 | 生イベント | `EventBatch` / `EventWindow`（x, y, t, p） | ○ | 詳細画面のみ（間引き点群） | **既定 ×** | **× 経路なし** |
| L1 | 中間表現 | グリッド集計、Voxel、重心、bbox | ○ | 詳細画面のみ | 既定 × | **× 経路なし** |
| L2 | 特徴量 | `FeatureFrame` / `SmoothedFeatures` | ○ | 詳細画面のみ | 既定 ×（`save_features` で可） | **× 経路なし** |
| L3 | 抽象状態 | `StatusSnapshot`（状態・継続時間・連続集中） | ○ | 全画面 | 期間制限付きで可 | **× 版 2.0 では経路なし** |

**版 2.0 では L3 ですら端末外へ出す経路が無い。** 将来 EXT-1 で共有機能を作る場合のみ、
L3 に限って外へ出せることとする。

### 2.1 メモリ上の保持時間

| データ | 保持 | 破棄タイミング |
|-------|------|--------------|
| `EventBatch` | 取得キュー内のみ | 窓化した時点で参照を捨てる |
| `EventWindow` | 特徴量抽出中のみ | `FeatureFrame` 生成後に破棄 |
| 間引き点群（`DetailFrame.preview_*`） | 1 フレーム分 | 詳細画面を閉じた時点で生成を止める |
| `FeatureFrame` | 直前 1 件 + 集約値のみ | `FeatureHistory` は eps 系列（60 秒分）だけを保持し、座標系列を保持しない |
| `HistoryEntry`（抽象状態） | `history_retention_minutes` | 期限超過時に `DurationTracker` が削除 |

**生イベント配列をリストに貯め込む実装を書いてはならない。**

## 3. 画面ごとの表示可否

### 3.1 常駐ウィジェット

| 表示する | キャラクター、状態名（日本語）、継続時間、状態履歴ストライプ、休憩促しバナー |
|--------|---|
| **表示しない** | 点群、特徴量、イベント数、座標、領域名、信頼度の数値 |

### 3.2 詳細画面

| 表示する | L0〜L3 すべて（本人の端末上、本人だけが見る前提） |
|--------|---|
| 必須表示 | `PRIVACY_NOTICE_JA`「RGB映像は使用していません / データはこの端末の外に出ません」 |
| 注意 | この画面をプロジェクタや画面共有に映すと L0/L1 が第三者に見える |

### 3.3 UI に出さないもの（版 2.0 の方針）

**ユーザに見せる画面はスマートに保つ。** 次のものは UI に常時表示しない。

| 出さないもの | どこに書くか |
|------------|------------|
| 「離席中は推定です」といった注記 | 本書 §6 と [status-definition.md](status-definition.md) §10 |
| 「イベントデータからも形状が推測されうる」旨（`PRIVACY_CAVEAT_JA`） | README と本書 §6 |
| 信頼度の数値 | 詳細画面のみ |
| 内部指標（eps、ルール ID など） | 詳細画面のみ |

`PRIVACY_NOTICE_JA` は詳細画面にのみ 1 行で置く。ウィジェットには出さない。
免責を並べるより、**既定で何も保存せず何も送信しない実装**で担保する。

## 4. 停止機能の仕様

| 操作 | 内部の挙動 | 表示 |
|------|-----------|------|
| 推定停止（PV-7） | `PipelineRunner.set_paused(True)`。入力の `read()` を止める。窓化・特徴量計算も止まる | 「推定を停止しています」 |
| 推定再開 | `set_paused(False)`。全コンポーネントを reset し `STARTING` から再開 | 「起動中です」→ 通常表示 |
| アプリ終了 | 入力を close。履歴はメモリ上のみなので消える | – |

停止中は休憩促しフラグを立てない（[status-definition.md](status-definition.md) §3.3）。

## 5. 表現ルール

### 5.1 使ってはならない表現

| 禁止 | 理由 |
|------|------|
| 「完全に匿名です」「プライバシーは完全に守られます」「安全です」 | 保証できない。イベントデータからも動きの形状は推測されうる |
| 「映像を記録していないので個人情報はありません」 | 動きのパターン自体が個人情報になりうる |
| 「不在です」「席にいません」 | 人の所在を断定する。イベントカメラでは静止した在席と離席を区別できない |
| 「〇〇さんはタイピングしています」 | 個人の特定 + 操作内容の断定。どちらも範囲外 |
| 「集中度 78%」「サボっている」「離席が多い」 | ユーザの行動を評価する表現 |

### 5.2 使ってよい表現

| 推奨 | 用途 |
|------|------|
| 「RGB映像は使用していません」 | 事実。詳細画面に表示 |
| 「データはこの端末の外に出ません」 | 事実。詳細画面に表示 |
| 「イベントデータからも動きの形状が推測される可能性があります」 | 限界の明示。**README と本書に記載。UI には出さない** |
| 「離席中」「集中」「非集中」 | 状態名。断定を避けた短い名詞形 |
| 「そろそろ休憩しませんか」 | 休憩促し。提案であって指示ではない |

## 6. 残るリスクと限界（正直に書く）

README にも要約を掲載する。**「安全です」で終わらせないこと。**

| # | 残るリスク | 説明 | 緩和策 |
|---|-----------|------|--------|
| L1 | イベントデータから動きの形状が推測されうる | 十分な密度のイベント列があれば、手の動き・物体の輪郭・タイピングのリズムが再構成されうる。「輝度変化だけだから何も分からない」は誤り | 生データを保存せず、端末外へ出す経路を持たない |
| L2 | 詳細画面を画面共有・録画すると L0/L1 が漏れる | DeskMate 自身は防げない | 詳細画面は既定で閉じており、開いている間しか点群を生成しない |
| L3 | 抽象状態の時系列からも生活パターンが推測されうる | 「毎日 14 時に離席」といった情報は残る | 履歴の保持期間を設定可能にし、既定 60 分。永続化しない |
| L4 | **「離席中」が誤って出る** | 着席したまま静止していると `away` になる | `away_seconds = 30.0` と最小継続時間 5 秒で頻度を下げる。UI で言い訳せず、閾値で対処する |
| L5 | 休憩促しが誤ったタイミングで出る | 推定は完全ではない | 「あとで」でスヌーズできる。音もポップアップも出さないので無視できる |
| L6 | 同室の他者の動きが写り込む | カメラは机上を向いているが、背後の通行人などが入りうる | 領域設定で机上に限定するよう案内する。個人の識別は行わない |
| L7 | 設定を変更すれば保存を有効化できる | 意図的な有効化は防げない | 既定無効 + 有効時の警告表示 + ログ記録 |
| L8 | ローカルの `data/` や `logs/` は OS のユーザ権限でしか守られない | ディスク暗号化・アクセス制御は OS 任せ | `data/` を `.gitignore` に入れる。既定で何も書かない |

## 7. ネットワークについて

**版 2.0 では通信機能を一切実装しない。**

- 送信・受信を行うライブラリ（requests / httpx / websockets / socket）を依存に含めない。
- `SourceKind` からネットワーク系の種別を削除済み。
- 入力は Metavision SDK（ローカルデバイス）・ダミー・ローカルファイルの 3 経路のみ。
- 将来 EXT-1 で共有機能を作る場合の必須条件:
  1. 送出できるのは `StatusSnapshot.to_public_dict()` の形式のみ
  2. 待ち受けはローカルネットワークに限定する
  3. UI に共有中であることを表示する
