# DeskMate プライバシー設計書

版: 1.0 / 最終更新: 2026-07-26

机の上には、書類・スマートフォン・PC 画面・私物といった個人情報が並ぶ。
DeskMate はそれらを「見ない」ことを前提に設計する。本書はその具体的な担保方法を定義する。

**重要な前提**: イベントカメラを使っているから安全、とは言わない（§5）。
本書は「リスクをゼロにする」文書ではなく、「何を取得せず、何を外に出さないか」を明示する文書である。

## 1. プライバシー要件一覧

| ID | 要件 | 実装上の担保 | 検証 |
|----|------|------------|------|
| PV-1 | RGB 画像を使用しない | 依存ライブラリに OpenCV / Pillow による撮像系を入れない。入力は `EventBatch`（x, y, t, p）のみを受け取る型で固定する | `requirements.txt` レビュー、`EventSource` の型 |
| PV-2 | PC 画面や書類の内容を取得しない | 画面キャプチャ API・ファイル走査・アクティブウィンドウ取得を一切実装しない | コードレビュー（`win32gui` / `mss` / `pyautogui` 等を import しない） |
| PV-3 | 生のイベントデータを原則保存しない | `privacy.save_raw_events` の既定 `false`。保存処理は `PrivacyGuard.assert_can_save_raw_events()` を通らないと実行できない | `tests/test_privacy_guard.py` |
| PV-4 | 生のイベントデータを外部へ送信しない | MVP に送信コードを実装しない。`PrivacyGuard.can_send_external()` は常に `False` | `tests/test_privacy_guard.py`、ネットワーク系ライブラリ非依存 |
| PV-5 | 状態推定は PC 内で完結する | クラウド API・外部推論サービスを使わない。全処理が `src/deskmate/pipeline/` 内で完結 | 依存レビュー |
| PV-6 | 外部へ共有するのは抽象化された状態のみ | 共有可能な形式は `StatusSnapshot.to_public_dict()` の 9 フィールドのみ（[status-definition.md](status-definition.md) §10） | `tests/test_privacy_guard.py`（フィールド集合の一致検査） |
| PV-7 | ユーザが推定処理を停止できる | 常駐ウィジェットの停止ボタン / トレイメニュー。停止中は入力の読み取り自体を止める | 手動確認 |
| PV-8 | ユーザが共有を停止できる | 共有停止で `SystemStatus.SHARING_OFF`。共有画面は「共有を停止しています」のみ表示し、直前の状態を残さない | 手動確認、`tests/test_ui_smoke.py` |
| PV-9 | 状態履歴の保存期間を設定できる | `privacy.history_retention_minutes`（既定 60）。`DurationTracker` が期限切れエントリを破棄 | `tests/test_duration.py` |
| PV-10 | デバッグ用保存機能は初期状態で無効 | `privacy.save_raw_events` / `save_features` / `logging.log_features` / `debug.enabled` すべて既定 `false` | `tests/test_config.py` |
| PV-11 | イベントデータからも形状や動きが推測されうることを明記 | 詳細画面と README に `PRIVACY_CAVEAT_JA` を常時表示 | 手動確認 |
| PV-12 | 「イベントカメラだから完全に匿名・安全」と表現しない | 全ドキュメント・全 UI 文言のレビュー項目 | コードレビュー、§5 の禁止表現リスト |

## 2. データの分類と扱い

DeskMate 内のデータを 4 段階に分類し、扱える範囲を固定する。

| レベル | 名称 | 具体例 | プロセス内 | 画面表示 | 保存 | 外部共有 |
|:-----:|------|--------|:---------:|:--------:|:----:|:--------:|
| L0 | 生イベント | `EventBatch` / `EventWindow`（x, y, t, p） | ○ | 詳細画面のみ（間引き点群） | **既定 ×** | **× 恒久禁止** |
| L1 | 中間表現 | グリッド集計、Voxel、重心、bbox | ○ | 詳細画面のみ | 既定 × | **× 恒久禁止** |
| L2 | 特徴量 | `FeatureFrame` / `SmoothedFeatures` | ○ | 詳細画面のみ | 既定 ×（`save_features` で可） | **×** |
| L3 | 抽象状態 | `StatusSnapshot`（状態・継続時間・信頼度・話しかけやすさ） | ○ | 全画面 | 期間制限付きで可 | **○（唯一許可）** |

### 2.1 メモリ上の保持時間

| データ | 保持 | 破棄タイミング |
|-------|------|--------------|
| `EventBatch` | 取得キュー内のみ（最大 64 件） | 窓化した時点で参照を捨てる |
| `EventWindow` | 特徴量抽出中のみ | `FeatureFrame` 生成後に破棄 |
| 間引き点群（`DetailFrame.preview_*`） | 1 フレーム分（次のフレームで置換） | 詳細画面を閉じた時点で `None` にする |
| `FeatureFrame` | 直前 1 件 + 履歴用の集約値のみ | `FeatureHistory` は eps 系列（float32, 60 秒分）だけを保持し、座標系列は保持しない |
| `HistoryEntry`（抽象状態） | `history_retention_minutes` | 期限超過時に `DurationTracker` が削除 |

**生イベント配列をリストに貯め込む実装を書いてはならない。** 窓化後は必ず参照を切る。

## 3. 画面ごとの表示可否

### 3.1 常駐ウィジェット

| 表示可 | キャラクター、抽象状態、継続時間、信頼度バー、共有 ON/OFF アイコン |
|--------|---|
| **表示不可** | 点群、特徴量、イベント数、座標、領域名 |

### 3.2 本人向け詳細画面

| 表示可 | L0〜L3 すべて（本人の PC 上、本人だけが見る前提） |
|--------|---|
| 必須表示 | `PRIVACY_NOTICE_JA`「RGB映像は使用していません / 生データは外部送信していません」<br>`PRIVACY_CAVEAT_JA`「イベントデータからも動きの形状が推測される可能性があります」 |
| 注意 | この画面をプロジェクタや画面共有に映すと L0/L1 が第三者に見える。UI に「この画面には机上の動きの情報が含まれます」と注記する |

### 3.3 共有画面

| 表示可 | キャラクター、抽象状態（7 種）、継続時間、話しかけやすさ（3 段階）、最終更新時刻 |
|--------|---|
| **表示不可** | 点群、特徴量、生イベント、机上の位置情報、領域名、操作対象の推測、イベント数、信頼度の数値、入力ソース名、エラーの詳細 |

実装上の担保:

1. `ShareWindow` は `UiBridge.detail_updated` シグナルに**接続しない**。
2. `ShareWindow` が参照してよいのは `StatusSnapshot` のフィールドのみ。
3. `tests/test_ui_smoke.py` で、`ShareWindow` の受信シグナル一覧に `detail_updated` が含まれないことを検証する。
4. 共有画面のコードレビュー時、`FeatureFrame` / `DetailFrame` / `EventWindow` の import が無いことを確認する。

## 4. 停止機能の仕様

| 操作 | 内部の挙動 | 本人画面 | 共有画面 |
|------|-----------|---------|---------|
| 推定停止（PV-7） | `PipelineRunner.set_paused(True)`。入力ソースの `read()` を停止し、キューを空にする。窓化・特徴量計算も止まる | 「推定を停止しています」 | 「共有を停止しています」 |
| 推定再開 | `set_paused(False)`。`windower` / `extractor` / `history` / `smoother` を reset し、`STARTING` から再開 | 「起動中です（推定準備中）」→ 通常表示 | 「準備中です」→ 通常表示 |
| 共有停止（PV-8） | `UiBridge.set_sharing_enabled(False)`。推定は継続。共有画面へは `system_status=SHARING_OFF` に差し替えた snapshot のみを渡す | 通常表示（アイコンが 🚫） | 「共有を停止しています」 |
| アプリ終了 | 入力を close、キューを破棄。履歴はメモリ上のみなので消える | – | – |

**共有停止中に直前の状態を残してはならない。** 「5 分前は集中傾向でした」という表示も禁止。

## 5. 表現ルール（禁止表現と推奨表現）

### 5.1 使ってはならない表現

| 禁止 | 理由 |
|------|------|
| 「完全に匿名です」「プライバシーは完全に守られます」「安全です」 | 保証できない。イベントデータからも動きの形状は推測されうる |
| 「映像を記録していないので個人情報はありません」 | 動きのパターン自体が個人情報になりうる |
| 「離席中」「不在です」「席にいます」 | イベントカメラでは静止した在席と離席を区別できない |
| 「〇〇さんはタイピングしています」 | 個人の特定 + 操作内容の断定。どちらも DeskMate の範囲外 |
| 「集中度 78%」 | 信頼度をスコアとして提示すると、能力評価に見える |

### 5.2 使ってよい表現

| 推奨 | 用途 |
|------|------|
| 「RGB映像は使用していません」 | 事実。詳細画面に常時表示 |
| 「生データは外部送信していません」 | 事実。詳細画面に常時表示 |
| 「イベントデータからも動きの形状が推測される可能性があります」 | 限界の明示。詳細画面と README に常時表示 |
| 「一定時間、動きを検出していません」 | 観測事実のみ |
| 「静かな状態が続いています」 | 同上 |
| 「現在の状態を判定できません」 | 同上 |
| 「話しかけやすそう」 | 推量形。断定しない |

## 6. 保存機能の設計（既定で無効）

MVP では以下の 3 つの保存機能を「口だけ用意し、既定で無効」にする。

| 機能 | 設定キー | 既定 | 有効化時の挙動 |
|------|---------|:----:|--------------|
| 生イベント保存 | `privacy.save_raw_events` | `false` | 詳細画面のボタン押下時のみ、直近 10 秒を `data/raw/YYYYmmdd_HHMMSS.npz` に保存。保存前に確認ダイアログを出し、保存先パスをログに残す |
| 特徴量保存 | `privacy.save_features` | `false` | `data/features/YYYYmmdd_HHMMSS.csv` に追記。座標系（centroid_x/y）は含めるが、点群は含めない |
| 特徴量ログ | `logging.log_features` | `false` | `level: DEBUG` のときのみ集約値をログ出力。**座標は常に出力しない** |

いずれも `PrivacyGuard` を経由しなければ実行できない。
`PrivacyGuard.assert_can_save_raw_events()` は設定が `false` のとき `PrivacyViolationError` を送出する。
この例外は**握り潰してはならない**（`except Exception: pass` の対象外）。

有効化されている間は、詳細画面の上部に赤字で「保存が有効です」を常時表示する。

## 7. 外部送信について

MVP では外部送信機能を**一切実装しない**。

- ネットワーク送信を行うライブラリ（requests / httpx / websockets / socket の送信用途）を依存に含めない。
- 将来 EXT-2（Raspberry Pi からの WebSocket 受信）を追加する際も、**受信のみ**とする。
  接続の確立に必要な最小限のハンドシェイク以外、PC からイベント関連データを送らない。
- 将来 EXT-8（共有画面をローカル HTTP で別デバイスに表示）を実装する場合の必須条件:
  1. 送出できるのは `StatusSnapshot.to_public_dict()` の形式のみ。
  2. 待ち受けはローカルネットワークのアドレスに限定する（`0.0.0.0` へのバインドは明示的なオプトインを必須にする）。
  3. `privacy.allow_external_send` を `true` にしない限り起動しない。
  4. UI に共有中であることを常時表示する。

## 8. 残るリスクと限界（正直に書く）

| # | 残るリスク | 説明 | 緩和策 |
|---|-----------|------|--------|
| L1 | イベントデータから動きの形状が推測されうる | 十分な密度のイベント列があれば、手の動き・物体の輪郭・タイピングのリズムなどが再構成されうる。「輝度変化だけだから何も分からない」は誤り | 生データを保存せず、外部にも出さない。詳細画面以外に点群を出さない |
| L2 | 詳細画面を画面共有・録画すると L0/L1 が漏れる | DeskMate 自身は防げない | 詳細画面に注記を表示。共有画面を用意して「見せる用」を分離する |
| L3 | 抽象状態の時系列からも生活パターンが推測されうる | 「毎日 14 時に小休止」といった情報は残る | 履歴の保持期間を設定可能にし、既定 60 分。永続化しない |
| L4 | 「話しかけやすそう」が誤って出ると、集中を妨げる | 推定は完全ではない | 推量形の表現に固定。信頼度が低いときは `undetermined`。最低保持時間でちらつきを抑える |
| L5 | 同室の他者の動きが写り込む | カメラは机上を向いているが、背後の通行人などが入りうる | 領域設定で机上に限定するよう案内する。個人の識別は行わない |
| L6 | 設定を変更すれば保存を有効化できる | 意図的な有効化は防げない | 既定無効 + 有効時の常時警告表示 + ログ記録 |
| L7 | ローカルの `data/` や `logs/` は OS のユーザ権限でしか守られない | ディスク暗号化・アクセス制御は OS 任せ | `data/` を `.gitignore` に入れ、誤コミットを防ぐ。既定で何も書かない |

これらを README と詳細画面に要約して掲示する。**「安全です」で終わらせないこと。**

## 9. レビューチェックリスト

- [ ] `src/deskmate/` 全体で `mss` / `pyautogui` / `win32gui` / `requests` / `httpx` を import していない
- [ ] `StatusSnapshot` のフィールドが [status-definition.md](status-definition.md) §10 の 9 項目（`status`, `label`, `animation`, `duration_seconds`, `confidence`, `approachability`, `approachability_label`, `system_status`, `updated_at`）+ 内部用 1 項目（`changed`）の計 10 個のみである。座標・特徴量のフィールドが 1 つも無い
- [ ] `share_window.py` が `FeatureFrame` / `DetailFrame` / `EventWindow` を import していない
- [ ] `ShareWindow` が `detail_updated` に接続していない
- [ ] `privacy.save_raw_events` / `save_features` / `logging.log_features` / `debug.enabled` の既定がすべて `false`
- [ ] 既定設定で起動 → 5 分放置しても `data/` 配下にファイルが生成されない
- [ ] 詳細画面に `PRIVACY_NOTICE_JA` と `PRIVACY_CAVEAT_JA` が常時表示されている
- [ ] 共有停止中、共有画面に直前の状態が残らない
- [ ] 全 UI 文言に §5.1 の禁止表現が含まれない
- [ ] ログに座標が出力されない（`level: DEBUG` でも）
- [ ] `PrivacyViolationError` が `except Exception` で握り潰されていない
