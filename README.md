# DeskMate

DeskMateは、イベントカメラで机上の動きを観測し、現在の作業状態を小さなキャラクターで
表示するWindows向けアプリです。

RGB画像やPC画面の内容は取得しません。イベントカメラが出力する「明るさが変化した座標・
時刻・極性」だけを使い、状態推定はWindows PC内で行います。

## 何ができるか

現在は動作確認用として、机上の動きを次の7状態で仮実装しています。
この状態構成は確定ではなく、実カメラのデータとハッカソンで伝えたい内容を確認してから
見直します。

| 状態 | 表示 |
|---|---|
| `focused` | 集中傾向 |
| `working` | 作業中 |
| `organizing` | 机上整理中 |
| `short_break` | 小休止 |
| `transition` | 状態が変化中 |
| `no_motion` | 一定時間、動きを検出していません |
| `unknown` | 状態不明 |

イベントカメラだけでは離席と静止を区別できないため、「離席中」「不在」とは表示しません。
たとえば`organizing`（机上整理中）は、実データから安定して区別できない場合や、
発表上の価値が低い場合は採用しない可能性があります。`transition`も利用者へ見せる状態ではなく、
内部的な表示安定化だけに使う選択肢があります。

画面は3種類あります。

- **常駐ウィジェット**: キャラクター、状態、継続時間、信頼度を表示
- **詳細画面**: イベント点群、動きの範囲、領域別活動量、特徴量、判定ルールを表示
- **共有画面**: キャラクター、抽象状態、継続時間、話しかけやすさの目安だけを表示

現在は以下の入力が利用できます。

- 340秒で複数の状態を巡回するダミーデモ
- `.npz`または`.jsonl`の録画イベント再生

Raspberry Piからのリアルタイム受信は、これから追加する機能です。

## システム構成

```text
GenX320
  ↓
Raspberry Pi 5（イベント取得・バッチ化）
  ↓ WebSocket（予定）
Windows PC（DeskMate）
  ↓
時間窓化 → 特徴量抽出 → 状態推定 → UI表示
```

Raspberry Pi側ではイベント取得と送信だけを行います。特徴量抽出や状態推定は行いません。

## ハードウェア側で必要な作業

ハッカソン発表までに、ハードウェア側で最低限必要なのは次の作業です。

1. GenX320をRaspberry Pi 5へ接続する
2. OpenEBまたはMetavision SDKでCDイベントを取得する
3. 取得したイベントをDeskMate形式へ変換する
4. 20～50ミリ秒程度にまとめてWindows PCへ送信する
5. 実カメラの録画データを`.npz`でも保存し、ライブ通信失敗時の予備にする
6. カメラをモニタ上部へ固定し、机全体が320×320座標内に収まるよう調整する

ハードウェア側からRGB画像、特徴量、状態名、信頼度を送る必要はありません。

## 必要なイベントデータ

1イベントにつき、次の4項目が必要です。

| フィールド | 型 | 内容 | 制約 |
|---|---|---|---|
| `x` | `uint16` | 横座標 | GenX320では0～319 |
| `y` | `uint16` | 縦座標 | GenX320では0～319 |
| `t` | `int64` | センサ基準の時刻 | マイクロ秒、単調増加 |
| `p` | `int8` | 極性 | 0または1 |

DeskMateの標準NumPy dtypeは次のとおりです。

```python
EVENT_DTYPE = np.dtype([
    ("x", "<u2"),
    ("y", "<u2"),
    ("t", "<i8"),
    ("p", "i1"),
])
```

MetavisionのHDF5ではフィールド順が`x, y, p, t`で、`p`が`int16`の場合があります。
DeskMateへ渡す前に`x, y, t, p`へ並べ替え、`p`を0または1の`int8`へ変換してください。

### 推奨する1バッチの内容

```text
seq             連番
sensor_width    320
sensor_height   320
t_start_us      バッチ先頭時刻
t_end_us        バッチ終端時刻
event_count     イベント数
events          x, y, t, p の配列
```

通信形式は次のどちらかを想定しています。

- JSON配列: 実装確認が簡単だが、イベント数が多いと重い
- `EVENT_DTYPE`の連続バイト列: 軽量で、ライブデモではこちらを推奨

JSONの場合の最小例です。

```json
[
  {"x": 125, "y": 210, "t": 123456789, "p": 1},
  {"x": 126, "y": 210, "t": 123456810, "p": 0}
]
```

## 録画データの形式

ライブ通信に失敗しても発表を続けられるよう、実カメラのデータを`.npz`で用意します。

```text
events    EVENT_DTYPEの構造化配列
width     320
height    320
```

概念例:

```python
np.savez(
    "recording.npz",
    events=events,
    width=np.array(320),
    height=np.array(320),
)
```

イベントは`t`の昇順で保存してください。Windows側でMetavision HDF5を直接読むより、
Raspberry PiまたはLinux環境で標準`.npz`へ変換する方法を推奨します。

## DeskMate側でこれから必要な実装

実カメラと接続するために必要な変更は入力部分だけです。

1. `WebSocketEventSource`を作成する
2. WebSocketで受信したデータを`EventBatch`へ変換する
3. 切断検出と再接続を実装する
4. `input/factory.py`へWebSocket入力を登録する
5. `config/default.yaml`へ接続先を追加する

状態推定、特徴量抽出、常駐ウィジェット、詳細画面、共有画面は変更しません。

接続後は詳細画面を見ながら、実際の机に合わせてキーボード・マウス・中央・左右の領域と
イベント発生率の閾値を調整します。

## これから決める状態パターン

現在の7状態をそのまま採用するのではなく、実カメラで次の動作を記録して、どこまで安定して
区別できるかを確認します。

- キーボードを継続して操作する
- マウスを断続的に操作する
- 書類や物を机の広い範囲で動かす
- 作業中に短く手を止める
- 長時間動きがない
- 照明変化やモニタのちらつきだけが入る

その結果と発表ストーリーを基に、次を決定します。

1. 利用者へ見せる状態を3～5種類程度に絞るか
2. 「机上整理中」を独立した状態として残すか
3. 「状態が変化中」を画面に出すか、内部処理だけにするか
4. 「集中傾向」と「作業中」を実データで区別できるか
5. 小休止と単なる入力の少ない作業を区別できるか
6. 信頼できない入力をどの条件で「状態不明」にするか
7. 各状態を発表中にどの動作で再現するか

各状態について、表示名、観測した動き、判定条件、最低継続時間、信頼度が低い場合の表示を
セットで決めます。イベントカメラから確認できない行動や心理状態は断定しません。

## ハッカソン発表までの最短チェックリスト

- [ ] 実カメラの点群が詳細画面に表示される
- [ ] 発表で使用する状態パターンと表示名を決める
- [ ] 各状態を実カメラ入力で再現できるか確認する
- [ ] キーボードまたはマウス操作で「集中傾向」か「作業中」になる
- [ ] 「机上整理中」を採用する場合、机の広い動きから安定して判定できる
- [ ] 動きを止めると「動きを検出していません」になる
- [ ] 通信切断時にアプリが終了せず、入力断を表示する
- [ ] 再接続後に推定が再開する
- [ ] 実カメラで録画した`.npz`を再生できる
- [ ] ライブ、録画、ダミーの順でフォールバックできる

発表だけを目的とする場合、exe化、インストーラー、HDF5直接読込、機械学習モデル、
ブラウザ共有、細かな設定画面は不要です。

## 起動方法

仮想環境が作成済みなら、プロジェクトルートの`Start-DeskMate.bat`をダブルクリックすると
ダミーデモが起動します。

PowerShellから起動する場合:

```powershell
.venv\Scripts\python -m deskmate --demo
```

画面を表示せず状態変化だけ確認する場合:

```powershell
.venv\Scripts\python -m deskmate --headless --demo
```

テスト:

```powershell
.venv\Scripts\python -m pytest -q
```

## プライバシー

- RGB画像を使用しない
- 生イベントと特徴量の保存は既定で無効
- 外部サービスへ送信しない
- 共有画面には点群、座標、特徴量を表示しない
- イベントデータからも動きの形状を推測できる可能性があることを明示する

詳細は[プライバシー設計](docs/privacy-design.md)を参照してください。
